# Pre-specified research log

This log records every research decision before the empirical numbers
are presented.  Anything not listed here would be a post-hoc choice and
should be either added prospectively or excluded from the final paper.

## 1. Research question

Does Apple option-implied volatility at an earnings announcement
forecast realized variance over the following ~20 trading days, and do
simple public conditioning variables improve the forecast in a strict
walk-forward exercise?

## 2. Fixed hypotheses

1. **H1.** Squared VXAPL has a positive association with subsequent
   20-trading-day realized variance.
2. **H2.** Thirty-day implied variance exceeds approximately matched
   20-trading-day realized variance on average; i.e. the matched-horizon
   variance spread ``IV - RV`` is positive on average across events.
3. **H3.** A regularized public-feature model may improve on an
   implied-variance-only model, but this hypothesis is treated as
   **unsupported** unless the regularized model improves out-of-sample
   forecast accuracy (R^2_OOS, RMSE, sign accuracy) in the strict
   walk-forward exercise.

## 3. Sample rules

* Daily panel: Apple split-adjusted OHLC, VXAPL OHLC, VIX close,
  VIX9D close, earnings flag, EPS estimate, EPS actual.  Source file:
  ``data/aapl_earnings_volatility_data.csv`` only.
* Event sample: rows with ``earnings_flag == 1`` from January 2015
  through October 2024 (40 events).
* Target: annualized 20-trading-day realized variance computed from
  squared close-to-close log returns:
  ``post_rv20_var = (252/20) * sum_{i=t+1..t+20} r_i^2``.
* Five-day realized variance: horizon-mismatch robustness test only.
* Initial walk-forward training: first 16 feature-complete events.
* Feature-complete = no NaN in
  ``[iv_var, pre_rv20_var, iv_runup_5, hist_abs_gap_4]`` and
  ``post_rv20_var``.
* The very first event is feature-incomplete because
  ``hist_abs_gap_4`` requires at least one prior event; 39 of 40 events
  are feature-complete, of which 16 are training and 23 are test.

## 4. Model choices fixed before judging results

* **Expanding historical mean:** simple expanding average of the
  training-window ``post_rv20_var``.
* **IV-only OLS:** ``post_rv20_var = alpha + beta * iv_var + epsilon``
  fit by ``numpy.linalg.lstsq`` with HC3 standard errors.
* **Multivariate descriptive OLS:** ``post_rv20_var`` regressed on
  ``[iv_var, pre_rv20_var, iv_runup_5, hist_abs_gap_4]`` with HC3
  standard errors.  Reported in the regression table only as a
  descriptive multivariate fit.
* **Ridge regression** with the same four predictors:
  * standardized using training-window means and standard deviations
    only,
  * intercept unpenalized,
  * closed-form NumPy solution ``(Z'Z + lambda * I) beta = Z'(y - ybar)``,
  * fixed penalty ``lambda = 10`` (pre-declared in this log),
  * zero-standard-deviation columns coerced to a zero slope.
* Walk-forward rule: forecast event ``i`` using events ``0..i-1`` only.
  No random train/test split.  No re-ordering.
* Bootstrap: 20,000 resamples with seed 42 for the percentile
  interval of mean ``vrp20``.

## 5. Evaluation metrics fixed before viewing the numbers

* **MAE** = mean(|actual - predicted|)
* **RMSE** = sqrt(mean((actual - predicted)^2))
* **R^2_OOS** = 1 - sum((actual - predicted)^2) /
  sum((actual - expanding-mean benchmark)^2)
* **Forecast correlation** = Pearson correlation between actual and
  predicted realized variance.
* **Variance-spread sign accuracy** = share of test events where
  ``sign(iv_var - predicted_rv) == sign(iv_var - actual_rv)``.

Model quality is judged using these metrics jointly.  No equity-curve
or Sharpe-style optimization is performed because the strategy outputs
are explicitly labelled variance-payoff proxies, not executable option
returns.

## 6. Exclusions and pre-committed labels

* Current-event ``eps_actual`` and ``eps_surprise_pct`` are excluded
  from every forecast because they are not available before the
  release.  They appear in the event-level CSV for description only.
* Any quantity built from ``IV - RV`` is called a "variance-payoff
  proxy" in the code, the tables and the paper, **never** "option
  return" or "trading P&L".
* The walk-forward loop and feature builder both raise informative
  errors for missing columns, invalid dates, insufficient history, and
  non-positive prices.  Silent NaN propagation is not allowed.

## 7. Results recorded after running the analysis

Numerical outputs were generated by

```bash
python -m src.run_analysis \
    --data data/aapl_earnings_volatility_data.csv \
    --output results
```

The pipeline produced:

* 40 quarterly events, 39 feature-complete events, 23 walk-forward test events.
* Mean VXAPL = 33.83%, mean post-event 20-day realized vol = 27.88%.
* Mean ``vrp20`` = 0.0328 with a 20,000-resample bootstrap 95% interval
  of [0.0150, 0.0500]; ``vrp20`` is positive in 70.0% of events.
* IV-only OLS slope = 0.5944, HC3 t = 2.70, R^2 = 0.260.
* Walk-forward IV-only RMSE = 0.0666, R^2_OOS = 0.115, spread-sign
  accuracy = 73.9%.
* The ridge public-feature model records RMSE = 0.0696,
  R^2_OOS = 0.036, sign accuracy below the IV-only model.

This negative-complexity result is **retained as the published
finding**.  Per the pre-specified rules in Sections 4-6, we do not
expand the predictor list, tune the ridge penalty against the test
sample, or rerun the experiment after viewing the numbers.
